# AGENTS.md

This repository builds Anki decks for [The Rust Programming Language](https://doc.rust-lang.org/book/).
Cards are written by an agent, then reviewed by a human.

## Layout

- `book/`: the book's source, a Git submodule.
- `cards/`: one TOML file per section, named after the section's source file, so `book/src/ch04-01-what-is-ownership.md` maps to `cards/ch04-01-what-is-ownership.toml`.
- `main.py`: builds the decks.
- `.github/workflows/build.yaml`: builds the decks and publishes them as a GitHub Release when a release tag is pushed.
- `dist/`: build output.

## Scope

Only chapters 1 to 21 of the book are covered.
Forewords, appendices and so on are out of scope.

## Card files

````toml
[[cards]]
id = "560bd493-6253-4bd1-847b-fccd2c304211"
type = "basic"
front = '''
front

```rust
println!("code");
```
'''
back = '''
back
'''

[[cards]]
id = "5a655805-af6d-43a4-ab29-c8e9029fa5a5"
type = "cloze"
text = '''
example {{c1::cloze}}
'''
extra = '''
optional extra explanation
'''

[[cards]]
id = "854a9430-f5d2-4a99-9198-fdebdfde726b"
type = "basic"
front = '''
...
'''
back = '''
...
'''
deleted = true
````

- `id` is a UUID generated by `uuidgen`. It is used as the Anki note GUID, so it must never change once committed.
- `type` is `basic` or `cloze`. It must never change once committed, because Anki will not update a note whose note type changed.
- `basic` cards have `front` and `back`. `cloze` cards have `text` and an optional `extra`.
- Content fields are Markdown.
- Indent code with tabs.
- Cloze deletions (`{{c1::...}}`) may appear in prose and inline code, but never inside fenced code blocks, because syntax highlighting would split the markers.
- To delete a card, keep its entry and add `deleted = true`. Never remove an entry.
- A section with nothing worth a card still gets a file, containing only a comment.

## Writing cards

- Write cards in Chinese. Keep technical terms in English.
- Aim for around 600 cards total.
- Test one fact per card. Keep answers short.
- Make every card self-contained.
- Restate ideas in your own words instead of translating the book's sentences.
- Do not use unnecessary context or examples.

## Verifying code

Every claim about code must be checked by actually running it using `rustc` or `cargo`.
Use the latest Rust edition.

## Workflow

The human asks for one chapter, for example, "generate chapter 4".

For each section in that chapter:

1. Read `book/src/<section>.md`.
2. Write `cards/<section>.toml`.

After all sections are done, stop and ask the human to review the cards.

## Building

`uv run main.py` writes `dist/rust-book-upto-<chXX>.apkg` containing every card from that chapter and all earlier chapters.

- Note types: `Rust Book Basic` with fields `id`, `front` and `back`, and `Rust Book Cloze` with fields `id`, `text` and `extra`.
- Decks: one subdeck per chapter, named like `Rust Book::04 Understanding Ownership`.
- Note type IDs and deck IDs are fixed constants.
- Markdown is rendered with markdown-it-py, and fenced code is highlighted with Pygments into static HTML.
- Deleted cards get the tag `rust-book-deleted`. There are no other tags.
